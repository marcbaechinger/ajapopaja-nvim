AJAPOPAJA                                                          *ajapopaja*

A sophisticated Neovim interface for LLM-powered code transformations and
reviews, featuring asynchronous Python RPC execution and history management.

                                 Type |gO| to see the table of contents.

==============================================================================
INTRODUCTION                                             *ajapopaja-intro*

Ajapopaja provides a bridge between your Neovim buffers and Python-based
Large Language Model (LLM) APIs. It allows for context-aware refactoring,
documentation generation, and code review.

Key Features:
- Asynchronous processing (non-blocking UI).
- Interactive multi-line prompt windows.
- Persistent history management of LLM outputs.
- Syntax-aware operations for Python, JS, Java, Kotlin, Lua, HTML, and CSS.

==============================================================================
USAGE                                                    *ajapopaja-usage*

Ajapopaja operates primarily on visual selections or the current cursor
context. 

Commands:

:AjapopajaHistory                                         *:AjapopajaHistory*
    Opens the history browser to view and reuse past LLM outputs.

:AjapopajaSelectModel                                 *:AjapopajaSelectModel*
    Opens a picker to switch between available LLM models.

:AjapopajaApplyLatest                                 *:AjapopajaApplyLatest*
    Automatically applies the most recent code transformation to the buffer.

==============================================================================
KEYBINDINGS                                        *ajapopaja-keybindings*

The following default keybindings are registered upon calling `setup()`.
Most bindings are prefixed with `<leader>a`.

NORMAL & VISUAL MODE ~

If a command exepcts a selection and is called in normal mode, the envire
buffer is selected.

<leader>at      Open a multi-line input window to describe a custom
                transformation for the current selection.
<leader>ar      Perform an LLM code review of the selection.
<leader>ai      Insert/Replace latest transformation from history (replaces
                selection).

VISUAL MODE ONLY ~

<leader>ad      Add or improve documentation (docstrings/comments).
<leader>af      Implement function: Completes the missing implementation 
                for a function stub or class.
<leader>au      Generate comprehensive unit tests for the selected logic.

NORMAL MODE ONLY ~

<leader>aw      Open the history manager window.
<leader>am      Select the active LLM model.
<leader>ap      Apply the latest transformation from history (replaces text).

==============================================================================
CONFIGURATION                                      *ajapopaja-config*

To initialize the plugin, add the following to your `init.lua`:

>lua
    require('ajapopaja').setup()
<

Note: The plugin requires a Python RPC host configured. Ensure your Python
environment has the necessary dependencies installed for the agent.

==============================================================================
API                                                       *ajapopaja-api*

M.setup()                                                 *ajapopaja.setup()*
    Initializes commands and keymaps.

M.create_multi_line_input({title}, {callback}) *ajapopaja.create_multi_line_input()*
    Opens a floating Markdown buffer for prompt entry. Explicitly restores
    window focus to the calling buffer upon submission or exit.

M.select({prompt}, {options}, {callback}, {current})      *ajapopaja.select()*
    A wrapper around |vim.ui.select| that ensures the current option is
    prioritized and the UI event loop is scheduled correctly via 
    |vim.schedule|.

==============================================================================
FAQ                                                        *ajapopaja-faq*

Q: How do I change the model?
A: Use `<leader>am` or `:AjapopajaSelectModel`.
